# crypto-lesson-encoding

**编码（encoding）不是加密（encryption）**。

- 编码是「同一份数据换一种写法」。它没有密钥，映射规则完全公开，任何人都能还原。存在理由是**通道限制**：
  HTTP 头只能放 ASCII、JSON 只能放文本、终端会把控制字符吃掉、URL 里 `?` `&` `/` 有语法含义。
- 加密是「让别人读不懂」。它有密钥，没有密钥就算知道算法也读不出来。

三个最常撞见的编码，判据看字符集：

| 编码 | 输出字符集 | 长度特征 | 每字节开销 |
|---|---|---|---|
| base64 | `A-Z a-z 0-9 + /`，末尾可能 1~2 个 `=` | 长度是 4 的倍数 | 4/3 倍 |
| hex | `0-9 a-f`（或大写） | 长度是偶数 | 2 倍 |
| URL 百分号编码 | 普通字符 + `%XX` 三元组 | 变长 | 每个 `%XX` 3 字符 |

### 关于本题
每段解出来只是一段纯文本，**按 SEG1 + SEG2 + SEG3 拼接**才行。
## 四、原理

**base64 为什么是 4/3 倍。** 它把输入按 3 字节（24 bit）分组，再切成 4 个 6 bit 的片段，
每个片段查表映射到 64 个可打印字符之一。24 bit 正好被 6 整除，所以不跨组浪费；
输入长度不是 3 的倍数时用 `=` 补齐，这也是「长度必为 4 的倍数」的来源。
它所解决的问题是：把任意二进制塞进只允许可打印 ASCII 的通道（邮件、HTTP 头、JSON 字段）。
解码是确定性的查表逆运算，没有任何密钥参与。

**hex 为什么是 2 倍。** 一个字节 8 bit，用两个十六进制数字表示（每数字 4 bit），
字节与文本一一对应，没有分组、没有补齐、没有任何歧义。它是最不容易出错的表示法，

**URL 百分号编码为什么变长。** URI 里 `?`、`&`、`=`、`/`、`#` 有语法含义，
空格在报文里也容易出问题，所以这些字节要写成 `%XX`。百分号编码可以把**任意**字节写成 `%XX`，
不必只编码特殊字符，附件里那段就是全量编码，解码器照样能还原。
